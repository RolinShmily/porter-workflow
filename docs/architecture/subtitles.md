# 字幕

## 两条来源路径

`transcribe` 阶段有两条路，由平台规格和请求共同决定：

1. **平台原生字幕轨**（`PlatformSpec` 声明支持字幕的平台，如 YouTube、
   Bilibili、TikTok）。优势是精确的拼写、标点和专有名词，且零识别成本。
   如果平台还提供中文轨且被选中，翻译阶段可以整段跳过。
   **这是请求而不是保证**：抓取可能因限流失败，失败后回退到 ASR。
2. **语音识别**（X/Twitter、Instagram，或没有原生轨时）。按 ASR 回退链依次
   尝试后端。

`porter.core.asr.platform_subs` 只负责读取 PREPARE 已经抓下来的字幕文件；
它**不是** `AsrBackend`，没有 `available()` 探测，也不参与回退顺序。

请求里显式给出 `--subtitle-file` 时，该文件成为源字幕轨，优先于平台轨和 ASR。
这条路径用于“视频没有字幕轨、也没有可用 ASR”的情况，避免猜测同目录 `.srt`
到底是源字幕还是译文。

## ASR 回退链

默认顺序（第一个可用的胜出）：

| 顺序 | 后端 | 前提 |
| --- | --- | --- |
| 1 | `whisper-local` | 安装 `[asr-local]`；无需 Key、可离线 |
| 2 | `whisper-api` | OpenAI 兼容的 Whisper Key |
| 3 | `videocaptioner` | 用户自行安装的外部 CLI（GPL-3.0） |

`--asr-engine` 或 `asr.engine` 会把指定后端**提升到最前**，其余仍作为回退。

链的规则：

- `available()` 是廉价探测，永不抛异常。
- 后端返回空结果视为失败，不是成功。
- 后端失败只记录并继续；`JobCancelled` 立即向上抛。
- 平台字幕路径成功时，不会调用任何 ASR 后端。

## 翻译回退链

默认顺序：

| 顺序 | 后端 | 前提 |
| --- | --- | --- |
| 1 | `llm` | 配置了 LLM Key；唯一能边翻译边修 ASR 错误的后端 |
| 2 | `bing` | 免 Key，逆向端点，未验证 |
| 3 | `google` | 免 Key，逆向端点，未验证 |
| 4 | `mymemory` | 免 Key，有文档的公开 API |
| 5 | `videocaptioner-llm` | 外部 CLI |
| 6 | `videocaptioner` | 外部 CLI |

`--translator` 同样只做“提升到最前”，不做过滤：指定后端限流时，作业不会死，
而是继续尝试其他后端。

### CJK 自检

免 Key 后端可能返回 HTTP 200，却把输入原样带回（反爬、语言对不支持、额度耗尽）。
如果不检查，每条 cue 都有非空 `target_text`，看起来翻译成功，BURN 也成功，
最终得到一条双语视频里两条相同的英文轨，作业还报告 DONE。

因此每个后端的结果都要通过 `has_chinese_translation()`：目标语言是中文却没有
CJK 字符时，按失败处理，换下一个后端。这是“链”而非“for 循环”的主要原因。

## 句子级翻译与碎片重构

ASR 和平台自动字幕常常给出滚动碎片（YouTube 自动字幕每 2–3 个词一条）。
逐条翻译会得到语序颠倒的碎词。翻译阶段因此做三件事：

1. **合并短碎片**（`merge_short_fragments`），把相邻过短的 cue 合成可翻译的句。
2. **重构句子**：按语法、标点和静音间隙切分，得到 `TranscriptSentence`。
3. **按中文意群重新断句**：单行 ≤ 20 字，时间戳按字数比例平滑分配。

翻译作用在**句子**上，而不是 cue 上；译完再切回带时间戳的 cue。因此输出 cue
数量可以与输入不同，cue 列表是**被替换**而不是被标注。

**副作用（重要）**：对已经是句级切分的字幕，合并仍可能发生。实测 3 条输入
可能变成 2 条输出，把两个不相关的短句并成一条；合并后的 cue 时间跨度正确覆盖
原 cue，所以行为正确但边界变了。CLI 与 MCP 都会报告
`input_cue_count` / `cue_count` / `cues_merged`，不会静默改变。

## 已知脆弱点

1. **`bing` 的分隔符会被重写。** 批量请求用 `\n[[|]]\n` 分隔；段数对不上时
   降级为逐句请求，而不是整条后端失败。
2. **`google` / `mymemory` 会限流（HTTP 429）**，尤其在反复探测之后。
   这是环境性的，等一会儿或换后端。
3. **`videocaptioner` 是外部进程。** GPL-3.0、`python<3.13`，只能由用户安装后
   通过 `subprocess` 调用；porter 不 import 它。
4. **平台字幕抓取会失败**，尤其在限流时；回退到 ASR 是设计内行为。
